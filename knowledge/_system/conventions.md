## Overview

The knowledge base is a file-system directory tree under `knowledge/`. Every directory has an `00-INDEX.md` with a tag-presence matrix. Every content file has YAML frontmatter and follows one of 5 templates with a predictable section ordering convention.

## Key Rules

- **No depth limit.** Metadata handles navigation, not folder depth.
- **One concept per file.** If a file exceeds ~50 lines in any section, split it.
- **Entry point is always the index.** The LLM never guesses file paths.
- **Frontmatter is extensible.** New metadata keys can be added freely.
- **Tags are kebab-case** (e.g., `durable-objects` not `Durable Objects`).
- **`relates:` paths** are relative to `knowledge/` root.
- **Skill files** (`skills/`) coexist as ~50-line quick-refs. The KB holds depth.

## Reading Flow

```
Task → extract tags → read domain 00-INDEX.md
                     → scan tag matrix → select files
                     → read selected files (frontmatter confirms relevance)
                     → follow cross-references if needed
```

## Writing Flow

```
Learn Phase → new information
1. Read _system/conventions.md and _system/templates.md
2. Read domain/topic/00-INDEX.md → find or create place
3. Write/update atomic file
4. Update index tag matrix
5. Update _tags.md if new tags introduced (Claude Code: auto-regenerated by Stop hook — skip this step)
```

## Staleness

Every file has `updated:` in frontmatter. Files >30 days old get flagged for review during Init phase.
